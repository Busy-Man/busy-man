대화 로그·질문·정답·함정 단서를 담는 정적 JSON. 담당: B.

코드에 텍스트를 박지 않고 여기서 읽는다. AI로 생성한 것을 그대로 커밋한다.

`day1.json`의 스키마는 8/4에 확정했다. **B**가 AI로 뽑는 JSON과
`phone.js`·`quiz.js`가 기대하는 모양이 어긋나면 8/5 병합일에 드러나고,
그날은 고칠 시간이 없다.

> 이 문단은 원래 "A가 AI로 뽑는 JSON"이었다. 위 3행("담당: B")과 자기모순이었고,
> 과거 커밋에서 `docs/team-plan.html`의 A/B를 바꿀 때 접점·콘텐츠 서술이 빠진 흔적이다.
> **`AGENTS.md` §2·§3에 남아 있던 같은 뒤집힘은 `e7ed1ee`에서 정정됐다.**

## 스키마

```
chrome       { clock, channel }          폰 상태바
laneNames    ["왼쪽","가운데","오른쪽"]   길 안내 — 아직 부르지 않는다 (AGENTS.md §3 열림)
mapTemplate  "… {lane}"
feedback     { correct, wrong, timeout, penaltySlow, penaltyGauge }
messages     [{ from, kind, text }]      kind = person | notice | map
quizzes      [{ sourceMessageIndex, prompt, choices[3], answer }]
```

`penaltySlow`·`penaltyGauge`는 8/5에 늘었다. 오답 패널티가 **감속 / 게이지 감소 2종 중
랜덤**으로 되살아났는데 룰렛·카드 연출이 보류라, 어느 쪽이 걸렸는지 알릴 곳이
모달 글자뿐이기 때문이다.

`sourceMessageIndex`는 해당 질문의 답 근거가 되는 `messages` 배열의 0부터 시작하는
인덱스다. `quiz.js`는 그 메시지가 실제로 표시된 뒤 활성 시간 3초가 지나기 전에는
질문을 열지 않는다.

## 분량 — 문자 58개 · 질문 20문항

```
문자 개수 = 스테이지 초 ÷ 2.6 = 150 ÷ 2.6 ≈ 58
질문 개수 = 스테이지 초 ÷ 주기 = 150 ÷ 7  ≈ 20
```

- **스테이지 150초** — `AGENTS.md` §3의 90~150초 중 **상한**을 잡았다.
  모자라면 순환하는데, 한 판에 같은 문자가 두 번 지나가면 8/8 촬영본에 그대로 보인다.
  짧은 판에서 남는 것은 문제가 안 된다
- **모달 중에는 스트림이 멈춘다.** 그래서 질문 20개 × 10초는 이 계산에 들어오지 않는다.
  안 멈췄다면 벽시계 350초 기준으로 135개가 필요했다
- **질문 20개는 「풀」이다.** 최종적으로는 풀을 키워 인플레이에서 랜덤으로 뽑아
  단조로움을 없애는 방향이고, 지금은 풀이 한 판 분량과 거의 같아 순차로 쓴다

## 보기 순서 — 여기서 흩지 않는다

**`quiz.js`가 모달을 띄울 때마다 보기를 섞는다.** 그래서 `answer`가 한 자리에 몰려 있어도
찍기로 통과할 수 없고, JSON에서는 보기를 **자연스러운 순서**(시각순·오름차순)로 둔다 —
사람이 정답을 눈으로 검토할 수 있는 쪽이 낫기 때문이다.

JSON 쪽에서 정답 위치를 흩어 놓는 방법도 있었지만 그건 한 판 안에서만 고른다.
다시 하면 같은 자리라 외우면 그만이고, `docs/balance-todo.md` §2의 판정 실험
(*"전부 찍기만 해서 클리어되는가"*)이 두 번째 판부터 무의미해진다.

질문은 전부 문자에 실제로 나온 사실을 묻고, 근접한 숫자를 함정으로 심었다 —
`203호↔302호`, `NAN-417↔NAN-471`, `4,500원↔5,400원`, `v2.3.1↔v2.1.3↔v2.3.2`.

생성에 쓴 프롬프트는 훅이 `docs/ai-log/raw/`에 자동으로 남긴다.
웹 대화 등 훅이 못 잡는 도구를 썼다면 원문을 직접 그 파일에 붙여넣는다 —
제출물 4번(AI 활용 기술 문서)에서 이 부분이 가장 큰 재료다.
