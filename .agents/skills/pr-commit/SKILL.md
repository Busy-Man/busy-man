# pr-commit

**규칙은 `AGENTS.md` §1(파일 소유권)과 §5(커밋과 브랜치)에 있다. 시작할 때 그 파일을 읽는다.**
여기에 규칙을 옮겨 적지 않는다 — 두 벌이 되면 어긋났을 때 어느 쪽이 맞는지 알 수 없다.
여기 있는 것은 **순서**뿐이다.

## 순서

**1. 읽는다**

- `AGENTS.md` §1, §5 — 소유 경계, `type(scope)` 유효값, 본문 형식
- `git status --short --branch`, `git diff`, `git diff --staged`
- `git log --oneline -5` — 이 저장소의 메시지 결이 어떤지

**2. 브랜치를 확인한다**

`main`이면 **멈추고** 브랜치를 먼저 만든다. §5가 main 직접 push를 금지한다.

브랜치가 없으면 작업 성격에 맞는 이름을 제안한다 (`feat/…` `fix/…` `chore/…` `docs/…`).

**3. 소유 경계를 점검한다**

변경된 파일이 `AGENTS.md` §1에서 **다른 사람 담당인지** 본다.
섞여 있으면 커밋하기 전에 알린다.

```
⚠ src/phone.js 는 B 담당입니다. (§1)
  이 변경을 포함할까요, 되돌릴까요?
```

§1은 "고쳐야 할 이유가 생기면 고치지 말고 상대에게 말한다"고 정하고 있다.
자동으로 판단하지 말고 사람에게 묻는다.

`src/state.js`가 섞여 있으면 **접점이 4개를 넘는지** 함께 본다 (§2).

**4. 커밋을 나눈다**

한 커밋 = 한 가지 이유. 되돌릴 때 같이 되돌아가야 하는 것끼리 묶는다.

나눌 후보를 보여주고 확인을 받는다. 파일 하나가 두 목적에 걸치면
그 사실을 말하고 어떻게 할지 묻는다 — 임의로 쪼개지 않는다.

**5. 메시지를 쓴다**

형식(`type(scope)`, 개요 + 리스트, 인용 표기)은 §5를 그대로 따른다. 여기서 다시 정하지 않는다.

리스트에 들어갈 것은 **판단이 갈렸던 곳, 대안을 버린 이유, 나중에 다시 논의될 것** 셋뿐이다.
바꾼 파일을 나열하거나 변경량을 적지 않는다 — diff가 말한다.

**6. PR 본문을 만든다**

`.github/pull_request_template.md`와 **같은 섹션**으로 쓴다.

```
## 개요
왜 이 PR이 필요한지 2~3줄. 문단 하나.
소유 경계나 병합 전 확인이 필요하면 여기 마지막에 ⚠ 한 줄.

## 변경 사항
- 커밋 제목급 요약 (`해시`) — 왜 그렇게 했는지 한 줄

## 체크리스트
템플릿 항목을 실제로 확인하고 표시한다. 확인 안 한 것을 체크하지 않는다.
```

- **섹션을 늘리지 않는다.** `## 비고`도 안 된다. 남길 말이 있으면 해당 섹션 안에 한 줄로 넣는다
- **체크리스트 항목 문구를 바꾸지 않는다.** 근거를 붙이려면 항목 뒤에 ` — 근거` 한 조각까지
- **굵은 글씨는 PR 전체에서 두 개까지.** 문단마다 굵으면 강조가 아니라 배경이 된다

base 브랜치를 확인한다. 기본은 `main`이다 (§5 — develop을 쓰지 않는다).

**7. 보여주고 멈춘다**

커밋 메시지 전문과 PR 본문 전문을 그대로 출력하고 확인을 받는다.
**승인 전에는 `git commit`도 `gh pr create`도 실행하지 않는다.**

```
[커밋 1/2] docs(agents): …
(본문 전문)

이대로 커밋할까요?
```

"커밋해줘"라는 요청은 이 확인을 대신하지 않는다. 사용자는 메시지를 아직 본 적이 없다.
그리고 §5가 squash·force-push를 금지하므로 **잘못 쓴 메시지는 push 후에 고칠 수 없다.**

## 하지 말 것

- `git add -A` / `git add .` — `.gitignore`가 모든 브랜치에 있지 않다.
  실제로 `.omc/`가 통째로 커밋된 적이 있다. **파일을 명시해 스테이징한다**
- `--amend`로 이미 push된 커밋 고치기, squash, force-push (§5 — 심사 요건)
- 사용자가 요청하지 않은 커밋·push·PR 생성
- **메시지 전문을 보여주지 않고 커밋·PR 만들기** (7단계)
- 메시지에 검증 로그나 변경 파일 목록 채워 넣기
- 산문 문단으로 이어 쓴 커밋 본문, 템플릿에 없는 PR 섹션
- 남의 담당 파일을 물어보지 않고 커밋에 포함하기
