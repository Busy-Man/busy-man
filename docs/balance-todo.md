## 1. 무시와 찍기

`game_balance_review.html` §05가 부등식 하나로 정리해 뒀다.
**손익분기 정답률** `p* = (L + C − I) / (G + L)` 이고, 그 문서가 제안한 목표 밴드는 **0.45 ~ 0.70**이다.

| 기호 | 뜻 | 현재 |
|---|---|---|
| `G` | 정답 이득 (초 환산) | 게이지 1칸 |
| `L` | 오답 손실 (초) | **랜덤 2종의 기댓값** — 아래 참조 |
| `C` | 응시 비용 | **모달이라 시간이 멈춘다 → C ≈ 0** |
| `I` | 무응답 벌 | **오답과 같다 (`I = L`)** — 확정 |

**양쪽 끝이 다 실패다.**

- `p*`가 **0.33 아래**로 내려가면 → 보기가 3개니까 **찍는 게 이득**이 된다.
  근거를 찾을 이유가 사라지고, 대화를 읽는 게임이 아니게 된다
- `p*`가 **0.75 위**로 올라가면 → **확신 없으면 무시**가 최적이 된다.
  질문 이벤트 자체가 회피 가능해진다

### 지금 구조는 찍기 쪽으로 기울어 있다

`I = L`과 `C ≈ 0`이 둘 다 `p*`를 끌어내린다. §05는 이걸 근거로 무응답 벌을 오답 벌의
0.2~0.4배로 작게 두라고 했지만 **그 권고는 따르지 않기로 했다** (`AGENTS.md` §3).
타임아웃과 오답을 같게 두는 편이 규칙이 단순하고, 8/6에 만져볼 노브는 어차피 남는다.

- [ ] `G`, `L`을 **초 단위로 환산**해서 적어둔다. 단위가 다르면 `p*`를 계산할 수 없다
- [ ] `p*`를 실제로 계산해 본다. 0.33 아래면 찍기가 최적이라는 뜻이다
- [ ] 너무 기울면 노브를 고른다 — `L`을 키우거나, `I`를 오답과 분리하거나, 모달 중에도 시간을 조금 흘린다

### `L`이 상수가 아니게 됐다 — 8/5

패널티 랜덤 부여를 되살렸다 (`AGENTS.md` §3). 오답 손실이 둘 중 하나로 뽑히므로
`L`은 이제 **기댓값**이고, 부등식에 항이 두 개 더 붙는다.

```
L = r · L_감속  +  (1 − r) · L_게이지        (r = 감속이 걸릴 확률)
```

- **`r`이 정해진 적이 없다.** 반반인지도 정하지 않았다
- **`L_게이지`는 게이지 잔량에 달려 있다.** 잔량이 0이면 그 항이 통째로 0이고,
  그만큼 `p*`가 내려간다 — `game_balance_review.html` §02가 말한 역상관이
  부등식에 그대로 나타난다. **알고 받아들인 구멍이므로 관측 대상이지 버그가 아니다**
- **`L_게이지`를 초로 환산하려면 `G`가 먼저 있어야 한다.** 게이지 1칸이 몇 초인지가
  정해지면 정답 이득과 오답 손실이 한꺼번에 정해진다. 여기부터 잡는다

- [ ] `r`을 정한다. 반반에서 시작할지, 감속 쪽으로 기울일지
- [ ] 게이지 감소량을 정한다 (몇 칸인가)
- [ ] `p*`를 **게이지 만땅일 때와 0일 때 각각** 계산한다. 두 값의 폭이 곧 역상관의 크기다
- [ ] 0일 때 `p*`가 0.33 아래로 내려가면 노브를 고른다 —
      게이지가 0이면 감속으로 대체하거나, `r`을 감속 쪽으로 기울인다.
      **8/3 기획 초안이 이미 같은 질문을 적어 뒀다** (`docs/기획 초안.md`) —
      *"스크랩이 없고, 게이지도 0일 때 → 그래도 랜덤으로? 아니면 감속 고정?"*
      새로 생긴 문제가 아니라 **그때부터 열려 있던 것이 되살아난 것이다**

## 2. 판정 실험 — 수치보다 먼저

§07이 제안한 것 그대로다. 수치를 만지기 전에 이것부터 한다.

- [ ] **질문을 전부 무시하고 클리어되는가?** 되면 강제성이 없는 것이다
- [ ] **전부 찍기만 해서 클리어되는가?** 되면 §05의 반대편 실패다

무시가 이득이 되는 구간을 의도적으로 만들어서 본다.

- [ ] 게이지가 가득 찼을 때 (정답 이득 0 — §04②는 **알고 남긴** 구멍이다)
- [ ] 마지막 질문 (남은 거리가 짧아 부스트 가치가 낮음)
- [ ] 갈림길 직전에 질문이 도착할 때

반대편도 본다 — **오답이 공짜가 되는 구간**이다. 8/5에 게이지 감소를 살리면서 생겼다.

- [ ] **게이지 0에서 게이지 감소가 뽑히면 실제로 아무 일도 일어나지 않는다.**
      초반 구간에서 이게 얼마나 자주 관측되는지 본다. 잦으면 초반이 무법지대가 된다

## 3. 수치가 아직 없는 것

- [ ] 감속량과 지속 시간 (기획 원문: *"패널티의 수위가 적절한가? 구현 후 경험으로 판단"*)
- [ ] **퀴즈 오답 감속과 보행자 충돌 감속을 갈라야 하는가** — 지금은 정도가 같다.
      둘은 `world.js`에서 곱해지므로(`AGENTS.md` §2) 겹쳤을 때 과한지 함께 본다
- [ ] 게이지 1칸이 몇 초를 벌어주는가 / 상한이 몇 칸인가.
      **`G`와 `L_게이지`가 여기 하나에 같이 매달려 있다** (§1)
- [ ] 랜덤 비율 `r`과 게이지 감소량 → §1에서 `p*` 계산과 함께 잡는다
- [ ] 대화 스트림이 흐르는 속도 (일단 프로토타입대로)

## 4. 정해야 닫히는 것

`AGENTS.md` §3의 열림 항목과 같은 건이다. 여기서 정하는 게 아니라 **합의해야 한다.**

- [ ] **질문 개수.** 정해진 적이 없다. 주기 6~8초와 스테이지 90~150초만 있어서
      그대로 두면 문항이 20개 안팎이 된다. 개수를 먼저 정할지 주기를 정할지 고른다
- [ ] **네비와 질문이 겹치는 타이밍.** §06이 규칙을 하나 남겼다 —
      *"네비 안내 구간과 질문 도착을 기본적으로 겹치지 않게 스케줄링하라.
      겹침이 기본이면 무시가 학습된다."* 겹침은 후반 난이도 장치로만 의도적으로 쓴다.
      이건 `content/*.json`의 데이터에 박히므로 **콘텐츠를 뽑기 전에** 정해야 한다
