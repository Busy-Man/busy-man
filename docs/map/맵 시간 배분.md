# 맵 시간 배분

`docs/map/맵 구조.jpg`(=`aaa.jpg`)의 맵 구조(그대로 유지)에서, **지금 `src/world.js`에 실제로
들어 있는 좌표**를 기준으로 구간별 시간을 역산한 기록. 문제 풀이 시간(모달 카운트다운)은
타이머가 멈추므로 여기 집계에서 제외했고, **감속이 한 번도 일어나지 않는다고 가정**한
순수 이동 시간만 다룬다.

> ⚠️ **이 문서는 두 번째 판이다.** 첫 판(8/4)은 S/T/C/B 구간마다 목표 초를 먼저 정하고
> 좌표를 거기 맞추려 했다(정수계획법으로 90~100초 밴드 최적화). 그 접근은 시간 기반
> 자동 좌표 생성 시도(8/5, D-010)로 이어졌다가 벽 구멍·배치 어긋남으로 폐기됐고,
> 대신 **손으로 그린 원본 좌표에 배율(`MAP_SCALE=2.1`)만 곱하는 방식**(L-017)으로
> 대체됐다. 즉 지금은 "시간을 먼저 정하고 좌표를 맞추는" 게 아니라 **"이미 정해진
> 좌표를 재서 시간을 읽어내는"** 순서로 뒤집혔다. 이 문서는 그 결과를 기록한다.

## 1. 그래프 재구성

`맵 구조.jpg`를 노드·간선 그래프로 옮기면 시작(START, `N1`)에서 갈림길이 상/중/하
3갈래로 갈라지고, 이후 `J1`·`J2`·`N3`·`N4`·`B7`에서 다시 갈라지거나 합류하며 두
종점(`END2`=상단 출구, `END3`=`B8` 옆 하단 출구)으로 모인다.

> ⚠️ **원본 이미지에 `C1` 라벨이 두 번 나온다** — 하나는 `N1~B3` 사이(중간 경로),
> 다른 하나는 `J2~N4` 사이(`J2` 우회로)다. 이 문서에서는 후자를 **`C2`**로 고쳐 불렀다.
> `world.js` 코드도 이 정정된 이름(`C2`)을 그대로 쓴다.

시작부터 끝까지 가능한 전체 조합은 **14가지**다 (상/중/하 선택 × 각 갈림길에서의
직진/우회 선택 × 마지막 `B7`/`J3`에서의 상단/하단 종점 선택) — 이 숫자는 첫 판과 같다.
그래프 구조 자체를 바꾼 적이 없기 때문이다.

## 2. 시간을 낸 방식 — 배정이 아니라 실측

`src/world.js`는 다음 세 값만 가진다.

```js
const SPEED = 6.0;
const MAP_SCALE = 2.1; // N_RAW(원본 손그림 좌표)에 곱하는 배율
```

노드 좌표(`N_RAW`)는 `맵 구조.jpg`에서 손으로 읽은 값이고, 실제 좌표는 `N_RAW × MAP_SCALE`이다.
따라서 두 노드 사이 이동 시간은

```
시간(초) = 거리(N_RAW 기준) × MAP_SCALE ÷ SPEED = 거리(N_RAW) × 0.35
```

**하나로 고정된다.** 첫 판처럼 S/T/C/B마다 "목표 초"를 따로 배정하지 않는다 —
신호등(T)·공사장(C)의 색칠 구역 폭(`ZONE_SEC=2.2초`)과 건물(B)의 체류 폭
(`BUILDING_DWELL_SEC=5.5초`)은 **이미 그 구간의 실제 거리 안에 들어 있는 값**이지,
거리 위에 추가로 얹는 시간이 아니다. §3의 T/C/B 행이 "가산 없음"이라 적힌 이유다.

**검증** — 이 방식으로 계산한 최단 경로(중간 직진→END3)가 55.5초로 나왔는데,
이는 8/5일 `MAP_SCALE` 도입 커밋(`6dfb9f0`)이 실측 보고한 값과 정확히 일치한다.

> 그림과 어긋나게 하는 것보다 낫다는 판단이다.

### T(신호등)·C(공사장) — 폭 2.2초, **별도 가산 없음**

`ZONE_SEC = 2.2`. T1~T5, C1~C3 전부 이 값을 쓴다(신호등/공사장 구분 없이 동일).
이 폭은 위 S 표의 거리 **안에 이미 포함되어 있다** — 예를 들어 `T1`은 `S2`+`S3`
(합계 8.4초)의 일부이지, `S2`+`S3`에 2.2초를 더 얹는 게 아니다.

### B(건물) — 체류 폭 5.5초, **별도 가산 없음**

`BUILDING_DWELL_SEC = 5.5`. B1~B8 전부 균일하다(첫 판의 10~15초 범위 배정은
폐기됐다 — L-017 커밋 메시지 "건물 체류 ≥5초 조정" 참조). 이 폭도 인접 S 구간의
거리 안에 포함된 값이다.
