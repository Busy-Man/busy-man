# ai-log/raw/

> ⚠️ **날짜별 원문 파일은 저장소에 두지 않는다. 노션에 보관한다.**
>
> `.gitignore`가 막고 있고, 파일은 각자 로컬에 계속 쌓인다.
> 사유는 아래 "왜 저장소에 두지 않는가", 보관 방법은 "노션에 보관한다" 참조.

**훅이 자동으로 쌓는 프롬프트 원문.** 사람이 손대지 않는다.

`.claude/hooks/log-prompt.mjs`가 두 단계로 채운다.

1. **UserPromptSubmit** — 프롬프트 원문을 `YYYY-MM-DD.md`에 append 하고 커밋 칸은 비워 둔다
2. **Stop** — 응답이 끝난 뒤, 그 사이 늘어난 커밋을 찾아 `반영 커밋` 칸에 채운다

기록하고 싶은 것은 "이 지시가 반영된 커밋"인데 프롬프트를 받는 시점에는 그 커밋이
아직 없기 때문에 두 단계로 나눴다. `git show --stat <해시>`로 산출물을 바로 볼 수 있다.

`반영 커밋: _없음_`은 그 턴에 커밋이 없었다는 뜻이다.
`<!--pending:...-->`가 남아 있으면 Stop 훅이 걸러진 것이므로 직접 찾아야 한다.

Stop은 **가장 최근 날짜 파일의 대기 항목 하나만** 채운다. 오늘 날짜로 고정해 열면
자정을 넘겨 끝난 턴이 영영 안 채워지고, 반대로 과거 항목까지 지금 HEAD로 채우면
나중 커밋을 엉뚱한 지시의 산출물로 붙이게 된다.

## 왜 저장소에 두지 않는가

**저장소에는 제출물과 소스만 둔다.** 프롬프트 원문은 제출물 4번(AI 활용 기술 문서)의
**원자재**이지 소스가 아니다. 정제된 기록은 `../ai_usage_log.md`에, 최종본은 문서 4번 PDF에 들어간다.

- Pages가 저장소 루트 전체를 서빙하므로, 두면 개발 원자재가 배포 사이트에 그대로 노출된다
- 심사 요건상 squash·force-push가 금지라 **올린 뒤에는 정정할 수 없다.**
  마감까지 계속 쌓이는 미확정 자료를 영구 이력에 넣지 않는다

유실 위험은 아래 노션 보관으로 막는다.

## 노션에 보관한다

파일이 날짜 단위이므로 **하루 한 번 수동으로 올린다.** 자동화는 두지 않았다 —
마감까지 많아야 파일 일곱 개라 스크립트·토큰·훅을 붙일 값이 나오지 않는다.

- 올릴 때 **파일명에 사람 구분을 붙인다** (`2026-08-05-A.md`). 둘이 각자 로컬에 쌓으므로
  구분이 없으면 같은 날짜 파일이 서로를 덮는다
- 문서 4번을 쓰는 8/8~8/9에 **양쪽 것을 내려받아** 합친다
- 올리는 것을 잊지 않도록 `/ai-log`가 매번 확인한다

## 정리하지 않는다

길어져도 압축·삭제하지 않는다. 여기가 제출물 4번의 원자재다.
정제된 기록은 `../ai_usage_log.md`에 따로 있다.

## 훅이 없는 도구로 작업했다면

훅은 Claude Code에서만 동작한다. Codex 등으로 작업했다면 그 세션의 프롬프트 원문을
직접 오늘 날짜 파일에 붙여넣는다. 형식은 훅이 쓰는 것과 맞추되, 안 맞아도 없는 것보다 낫다.
