# AI 로깅 체계 정합화

## Context

PR #1~#4가 병합되면서 저장소가 온전해졌고, **훅도 정상 동작을 시작했습니다** (`raw/2026-08-03.md`에 `23:33 · main` 항목이 자동 기록됨). 여기까지는 의도대로입니다.

문제는 그 사이에 **프롬프트 원문(raw)의 보관 정책이 바뀌었는데 문서가 따라오지 못했다**는 것입니다.

- 문서에 적힌 것: "공개 여부 **미결**이라 잠시 보류. 결정되면 `.gitignore` 블록을 지우고 커밋한다"
- 실제 결정: **저장소에 올리지 않는다. 노션에 수동 업로드해 보관하고, 문서 작성 시 다운로드한다**

그대로 두면 다음에 읽는 사람이 "곧 커밋할 것"으로 오해합니다. 특히 `raw/README.md`의 **"왜 커밋하는가"** 절은 이제 정반대 내용입니다.

정합성 점검 과정에서 구멍 3개가 추가로 드러났습니다.

1. `deep-interview-review-and-conventions.md`가 **`.omc/`에만** 있음 — 제가 만든 지침 §4("AI 명세는 `ai-log/specs/`로 옮긴다")를 정작 지키지 않은 상태. `.omc/`는 gitignore 대상이라 정리하는 순간 사라집니다
2. `AGENTS.md`에 **훅 승인 안내가 없음** — 팀원이 `/hooks`에서 승인하지 않으면 프롬프트 기록이 통째로 빕니다. 이번에 직접 겪은 문제입니다
3. 가이드라인 `### 두 개의 층` 제목인데 표는 **3행** — specs 층을 추가하며 제목을 안 고쳤습니다

여기에 더해 **렌더러가 three.js로 확정**됐습니다. 로딩은 **저장소 동봉**(`vendor/three.module.js`, 상대경로 import)입니다. CDN은 심사 당일 외부 서버 상태에 게임이 종속되고, `team-plan.html` §02가 이미 잘라낸 "마지막 날 백지" 리스크를 다시 들여놓기 때문입니다.

`AGENTS.md` §3이 렌더러를 **"열려 있음 — 합의 전에 코드를 쓰지 않는다"**로 묶어두고 있어, 이걸 풀지 않으면 `world.js` 착수가 규약상 막힙니다. 범위가 작으므로 같이 처리합니다.

**목표:** 문서가 실제 정책과 일치하게 만들고, 위 3개 구멍을 막고, 렌더러 확정을 반영합니다. 자동화·구현은 추가하지 않습니다(노션 업로드는 수동 결정, three.js는 주석·문서 반영만).

## 커밋 1 — raw 보관 정책 확정

`docs(ai-log): raw 보관 정책을 노션 수동 보관으로 확정`

### 사유 표현 — 아래 문구로 통일

이 사유는 팀원과 심사자가 읽습니다. **"어투가 구어체라서" 같은 표현은 쓰지 않습니다.**
근거로 약할뿐더러, 실제로 성립하는 이유가 따로 있습니다.

> **저장소에는 제출물과 소스만 둔다.** 프롬프트 원문은 제출물 4번(AI 활용 기술 문서)의
> **원자재**이지 소스가 아니다. 정제된 기록은 `ai_usage_log.md`에, 최종본은 문서 4번 PDF에 들어간다.
>
> - Pages가 저장소 루트 전체를 서빙하므로, 두면 개발 원자재가 배포 사이트에 그대로 노출된다
> - 심사 요건상 squash·force-push가 금지라 **올린 뒤에는 정정할 수 없다.** 마감까지 계속
>   쌓이는 미확정 자료를 영구 이력에 넣지 않는다
>
> 유실 위험은 노션 보관으로 막는다.

네 항목 모두 사실이며 검증됐습니다 — Pages branch 방식(`main`/root)이 루트 전체를 서빙하는 것,
`docs/team-plan.html` §05의 squash·force-push 금지, `대회_정보.md`의 제출물 구성.

파일마다 분량만 조절합니다. `.gitignore`는 3~4줄, `raw/README.md`는 위 전문, 나머지는 한 줄 요약.

docs/ai-log/raw/*.md
